# Адаптивные клиенты: ПК, Android, iPhone

Alpha UI собран; есть manifest и публичная offline-страница через service worker. Финансового offline cache, push, native пакетов и real-device QA нет. Остальной документ описывает также целевые возможности. [Текущее состояние](IMPLEMENTATION.md).

Статус: выбранная стратегия — один React/TypeScript PWA-клиент, cloud API и возможность Capacitor-пакетов позднее.

## Поддерживаемые поверхности

| Поверхность | Базовый доступ | Дополнительное поведение |
| --- | --- | --- |
| Windows/macOS/Linux | Адаптивный браузерный интерфейс | PWA install там, где поддерживается |
| Android | Chrome/совместимый браузер, тот же web URL | Установка PWA, камера/file picker, push по capability |
| iPhone/iPad | Safari и проверенные браузеры, тот же web URL | Home Screen app; push после установки и разрешения при поддержке |
| Native iOS/Android, позже | Capacitor с общей web-сборкой | Native push/share/camera plugins при конкретной необходимости |
| Внешние AI-клиенты | Remote MCP | Доступ к разрешённым данным/командам; не замена графического клиента |

Совместимость определяется возможностями браузера, не только user-agent. Основные деньги/планы/approval доступны без установки и push. На iOS Web Push для Home Screen apps появился с 16.4 и требует пользовательского разрешения; это не означает поддержку уведомлений любой обычной вкладкой. [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

Capacitor позволяет использовать web-код в native runtime. Магазинная публикация, подпись и тесты устройства — отдельный этап, не следствие наличия PWA. [Capacitor](https://capacitorjs.com/docs).

## Layout и доступность

Контентные breakpoints: compact <640 CSS px, medium 640–1023, wide ≥1024. Это starting design tokens, не определение типа устройства. Grid/flex, fluid widths, safe-area insets и ограничение длины строки; никаких фиксированных desktop canvas.

Телефон: один основной столбец и нижняя навигация. Планшет: детали могут открываться рядом. ПК: боковая навигация и две области, клавиатурные действия. Табличные финансовые данные на узком экране превращаются в карточки с сохранением значений и действий.

Контроль: 320/360/390/768/1024/1440 px, portrait/landscape, 200% text zoom, виртуальная клавиатура, длинные украинские/немецкие тексты. Touch targets проектировать не менее 44 CSS px. Фокус видим; статус не передаётся только цветом; screen-reader labels и reduced-motion обязательны.

Первый язык UI — украинский. Сообщения вынесены в i18n; деньги форматируются через Intl с currency/locale, даты — с IANA timezone. Backend возвращает codes/factors, не локализованные строки как бизнес-контракт.

## Сеть и offline

Worker живёт в облаке. Service worker отвечает за app shell и контролируемую доставку UI, а не за длительное исполнение задач.

По умолчанию persistent cache содержит только публичный app shell. Финансовые ответы, CV, approvals и provider tokens не кэшируются service worker. В уже открытом клиенте допускается последний снимок в памяти с as_of и явным offline/stale состоянием.

Offline можно просмотреть уже полученное и редактировать несохранённый локальный draft. Запись/approval требуют соединения и актуальной серверной версии; никакой скрытой очереди денежных мутаций или отправок. Persistent offline financial storage — отдельная возможность после оценки защиты общего устройства.

На reconnect запрашиваются версии, затем повторно валидируется draft. Logout очищает локальные данные; revoked session не продолжает API-доступ через cache.

## Обновления и уведомления

Job status доступен через polling; SSE ускоряет отображение, но его разрыв не теряет job. Восстановление страницы получает серверный результат по ID.

Push — opt-in подсказка об изменении, а не единственный способ получить результат. In-app inbox остаётся доступным. Notification payload минимален и не содержит баланс, CV или полный receipt. Повторный push дедуплицируется, не повторяет действие.

Service-worker update не перезагружает форму approval автоматически. Версия API совместима с предыдущей активной сборкой в период rollout; сервер отклоняет несовместимую старую команду понятным кодом.

## Проверка устройств

Текущий CI содержит Playwright tests для Desktop Chrome, Pixel 7/Chromium и iPhone 13/WebKit; их новый прогон пока не подтверждён. Firefox остаётся целевым дополнительным покрытием. Release gate отдельно включает настоящий iPhone/Safari и Android/Chrome: login, камера/выбор фото, safe areas, клавиатура, background/resume, PWA install и notification permission. Эмуляция WebKit в CI не объявляется полной проверкой iPhone.
