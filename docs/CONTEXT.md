# Контекст и действующие решения

Обновлено 2026-09-07. Документ различает замысел пользователя, выбранную техническую реализацию и исторические предложения.

## Текущее поручение владельца

После первоначального наполнения репозитория владелец поручил переписать проект под работу в облаке, выбрать наиболее подходящие языки и обеспечить адаптивность для разных LLM, ПК, Android, iPhone и других устройств.

Это поручение разрешает исполнителю выбрать конкретный stack и cloud architecture. Поэтому выбор Python/FastAPI + TypeScript/React/Vite + PostgreSQL, durable cloud jobs и общей PWA больше не помечен как ожидающий отдельной ратификации. Статус **DECIDED** означает выбранное в рамках поручения техническое решение; он не означает реализованный код или согласие владельца со всеми прежними AI-предложениями.

## Приоритет документов

Текущие STACK, ARCHITECTURE, CLOUD_EXECUTION, CLIENTS, LLM_ADAPTERS и ROADMAP определяют техническое направление. Предыдущая редакция scaffold остаётся в git history. Облачное выполнение теперь основное; внешний harness — дополнительный интерфейс/исполнитель, а не обязательный постоянно открытый runtime.

## Что сохраняется

Простой счётчик и понятные последствия покупки. Детерминированная арифметика. Долгосрочная экономия с сохранением полезности. Поиск дохода в разрешённых пределах. Чеки, банковские данные и Telegram по мере доказанной пользы. UNKNOWN, provenance, approvals и отзыв. BaseLineReduce и отсутствие календарных обещаний.

## Что изменено текущим поручением

| Вопрос | Предыдущая неопределённость | Текущее решение |
| --- | --- | --- |
| Runtime | Личная harness-сессия и будущий background provider | Cloud API/worker/scheduler с durable состоянием |
| Языки | Только рекомендации | Python backend/agents; TypeScript client; SQL state |
| Framework клиента | Next.js или React | React + Vite PWA; Capacitor при native-потребности |
| Устройства | Android/ПК; остальные позднее | ПК/Android/iPhone/tablet учитываются в первом UI и QA |
| Модели | MCP как основной шлюз | Отдельные outbound provider adapters и inbound remote MCP |
| Структура | Packages или множество engines | Один backend codebase, внутреннее Money, отдельные процессы по lifecycle |
| Технический roadmap | MCP после банков | Cloud foundation и model-neutral boundary раньше; product gates сохраняются |

## Что не ратифицировано автоматически

В последующем one-shot поручении владелец попросил реализацию с агентами. Исполнитель выбрал alpha money-policy, зафиксированную в MONEY/ADR-0002; это не личное принятие всех предложений v2. Historical product thresholds остаются нератифицированными. Самостоятельный Earn вне исходной последовательности Reduce — отдельное продуктовое изменение. Общий +15 п.п. не превращается в универсальную доказанную метрику.

Выбор hosting topology не создаёт ресурсов и не расходует бюджет. Названия провайдеров в adapter backlog не означают подключённые аккаунты. После one-shot поручения создана рабочая alpha-реализация; [IMPLEMENTATION](IMPLEMENTATION.md) отделяет код от остальных будущих функций.
