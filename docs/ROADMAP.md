# Облачный roadmap без сроков

Это текущая последовательность по поручению владельца от 2026-09-07: облачное выполнение, выбранный стек, разные LLM и адаптивные клиенты с первого рабочего релиза. Предыдущие R0–R18 сохранены в git history; карта ниже показывает их покрытие. Ни один runtime-этап ещё не выполнен.

| Срез | Что работает в конце | Exit gate | Покрытие старого roadmap |
| --- | --- | --- | --- |
| C0. Cloud foundation | React/Vite client, Python API, auth, PostgreSQL, worker/scheduler, реальная container-сборка и staging | Вход с телефона/ПК; чужие owner ID отвергаются; одна job переживает закрытие вкладки и restart worker | Основа R0, R15–R17 |
| C1. Cloud money | Ручной ввод, версии, обязательства, резерв/цель, детерминированная проверка | Money policy принята; инварианты и replay проходят; два устройства видят одну версию, конфликт не теряется | R1–R2 |
| C2. Model-neutral access | Remote MCP и ModelProvider, cloud inference job, quota/отмена/ожидание | Реальный MCP-клиент; одна task schema работает через два доступных providers; отключение клиента не останавливает cloud job | R8 |
| C3. Reduce plan | Текущая привычка → варианты → выбор → наблюдения → результат в облаке | Полный цикл, сохранение отказа, стоимость запуска, observed/scenario разделены; продолжение другой моделью | R5–R7 |
| C4. Источники | CSV/чеки, затем один read-only bank adapter | Нет двойного учёта; freshness/reconciliation/outage; приватные uploads и scoped доступ | R3–R4 |
| C5. Earn | Income gap, подтверждённый профиль, источники вакансий, drafts и pipeline | Нет выдуманных фактов; релевантность и время человека измерены; отправка отключена до C6 | R9–R12 |

## Зависимости

C1 зависит от C0 и денежной policy. C2 зависит от C0 и permissions; доступ к Money tools требует C1. C3 использует C1/C2, ручных наблюдений достаточно. C4 улучшает ввод и зависит от C1; банковский adapter не является условием работы облачного worker или MCP. C3 допускает ручное описание потребности, пока автоматическое обнаружение требует достаточных источников C4.

C5 в исходном продукте следует за Reduce/income-gap gate. Возможность независимого запуска Earn из v2 остаётся отдельным продуктовым решением; текущее поручение по облаку само по себе его не ратифицирует. C6 зависит от подготовленного C5 и разрешённого provider. C8 не включается первым релизом.

C7 описывает зрелость всего продукта, но ownership, минимизация данных, recovery и адаптивность реализуются уже в C0–C1. Нельзя отложить iPhone layout или durable jobs до конца roadmap.

## BaseLineReduce

Ручные деньги и обычный способ решения остаются baseline. Ввод cloud foundation обеспечивает требуемое место исполнения, а не доказывает полезность рекомендаций. C2 сначала проверяется технически; пользовательские вмешательства включаются после соответствующего продуктового gate. Провал полезности не маскируется добавлением банков и автономных откликов.

Безопасность/арифметика проверяются как корректность, ценность — наблюдениями. Стоимость hosting/inference входит в измерение механизма. Ни срок, ни зелёный документационный CI не открывают следующий продуктовый gate.

Первыми реализуются задачи [BACKLOG](BACKLOG.md). Спорные money thresholds и отдельные изменения v2 остаются отмеченными в [CONTEXT](CONTEXT.md).
