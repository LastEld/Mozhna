# Roadmap без сроков

Основа — восстановленный roadmap R0–R18. Каждый этап открывается при выполнении зависимостей и exit gate. Все этапы разработки пока не начаты; этот commit готовит только документы и структуру.

| Этап | Результат | Зависимость и критерий перехода |
| --- | --- | --- |
| R0 | Термины, baseline, критерии вреда | Протокол понятен и фиксируется до эксперимента; документация ещё не является полевым доказательством |
| R1 | Money Kernel | Сценарии и инварианты проходят; результат воспроизводится без сети/LLM |
| R2 | Ручной продукт | Ввод → счётчик → проверка покупки → запись; измеренная польза относительно baseline |
| R3 | Канонический учёт | R1–R2; импорт, provenance, аннотации, дубли и сверка проверены |
| R4 | Read-only банк | R3; один реальный provider, freshness, outage и reconciliation проходят |
| R5 | Потребности и привычки | R3; кандидат подтверждён человеком, ошибочные совпадения видны |
| R6 | Reduce | R5; сравнимые цены/объёмы, ограничения и затраты запуска проверены |
| R7 | Микроконтракты | R6; принятое изменение и наблюдаемый результат связаны, отказ сохраняется |
| R8 | MCP и каналы | Общие services; реальный MCP-client test, scopes и parity с API |
| R9 | Income gap | Денежный контракт; разовый кассовый разрыв не смешан с регулярным дефицитом |
| R10 | Публичные вакансии | R9 в исходной последовательности; факты профиля и релевантность проверены |
| R11 | Подключённые job-аккаунты | R10; конкретный поддерживаемый connector, scopes и отзыв |
| R12 | Черновики откликов | R10–R11 по нужному источнику; factual diff без выдуманного опыта |
| R13 | Подтверждённая отправка | R12; approval, expiry, stale, timeout и reconciliation проверены |
| R14 | Ограниченная автономность | R13; отдельный мандат, shadow-проверка, лимиты, kill switch |
| R15 | Android/ПК и дополнительные каналы | Проверенный web-сценарий; отдельная оболочка только при нужной функции |
| R16 | Production trust | Владение, секреты, экспорт/удаление и изоляция проверены для включённых функций |
| R17 | Эксплуатация | Restore, миграции, мониторинг, бюджеты повторов и восстановление задач |
| R18 | Экономика продукта | Измерены hosting/provider/inference costs и пользовательская ценность |

R16–R17 учитываются с первого рабочего среза, а не откладываются до конца таблицы.

## Что предложено пересмотреть в v2

Предложение v2: после надёжного минимального учёта проверять полный цикл одной привычки с тонким MCP, дать Earn самостоятельный вход и автоматизировать импорт отдельной ветвью. Это не принято автоматически. См. [CONTEXT](CONTEXT.md) и [ADR-0001](adr/0001-runtime-shape.md).

Пока порядок не пересмотрен явным решением, первый implementation scope — R1 и ручной путь R2. Банки, внешние отправки и автономность не нужны для его запуска.

## STOP

Ошибки денежных инвариантов, выдача чужих данных или действие вне полномочий блокируют зависимый релиз. Провал продуктового gate ведёт к пересмотру/сокращению механизма; новый слой не используется для сокрытия провала. Календарная дата сама по себе не открывает следующий этап.
