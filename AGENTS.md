# Инструкции для AI-разработчиков

Этот файл относится ко всему репозиторию.

- Читайте README, docs/CONTEXT.md, docs/STACK.md, docs/ROADMAP.md и конкретную задачу перед кодом.
- Выполняйте порученный срез до проверяемого результата. Папки и интерфейсы без работающего пути не означают готовую функцию.
- Текущий выбор cloud-first, Python/FastAPI + TypeScript/React/Vite + PostgreSQL, PWA и сменных LLM сделан по прямому поручению владельца. Не просите заново выбрать языки. Остальные спорные предложения v2 не ратифицированы автоматически; DECIDED не означает IMPLEMENTED.
- Сохраняйте детерминированное Money Kernel. LLM не устанавливает финансовую истину и не выдаёт разрешения.
- Не расширяйте scope до микросервисов, универсального DSL или переноса AMS без конкретной необходимости и задачи.
- Не добавляйте секреты, реальные выписки, CV, чеки или browser sessions. Примеры только синтетические.
- Не ослабляйте UNKNOWN, owner checks, approval, revoke и reconciliation ради успешного demo.
- Поддерживайте общие services для UI/API/MCP/worker. Длительные действия — durable cloud jobs, не in-process background task при HTTP-запросе. Не обещайте работающий MCP без реального клиента или multi-LLM без двух проверенных providers.
- Учитывайте ПК/Android/iPhone с первого UI. Клиентская capability не меняет права, план или финансовую policy. Генерируйте TypeScript API client из backend schema, не дублируйте Money.
- Проверяйте затронутые риски; не выдумывайте результаты, метрики, команду запуска или доступность интеграции.
- Выполняйте `python3 scripts/check_docs.py`. Runtime tests добавляются вместе с соответствующим кодом.
- В итоговом сообщении укажите результат, проверку и реальные ограничения. Новые approvals не требуются для уже порученных обычных изменений; принятие спорного продуктового решения нельзя подменять документационным статусом.
