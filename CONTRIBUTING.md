# Разработка MOZHNA

Сначала прочитайте [продукт](docs/PRODUCT.md), [контекст](docs/CONTEXT.md) и [backlog](docs/BACKLOG.md). Репозиторий находится на этапе документации.

## Изменение

1. Выберите конкретную задачу и критерий приёмки.
2. Создайте ветку `docs/...`, `feat/...` или `fix/...`.
3. Сделайте минимальный полный срез и обновите затронутые документы.
4. Выполните `python3 scripts/check_docs.py` и относящиеся к изменению runtime-проверки, когда они появятся.
5. Откройте PR: проблема, результат, проверка, ограничения.

Не публикуйте реальные финансовые данные, чеки, CV, credentials или сессии. Fixtures синтетические. Финансовые значения — integer minor units.

Выбранный по поручению cloud stack имеет статус DECIDED; повторный выбор языков не требуется. Новые невыбранные предложения отмечайте PROPOSED. Спорные продуктовые изменения v1/v2 не объявляйте принятыми автоматически.

Frontend TypeScript client генерируется из backend OpenAPI. Денежная логика остаётся Python domain. Проверяйте job resume, provider capabilities и responsive paths по реальной границе изменения.

## Definition of done

- Поведение соответствует критериям задачи; статусы в документации правдивы.
- Для функционального изменения есть воспроизводимая проверка существенного риска.
- Права, неизвестность и ошибки обработаны на реальной границе.
- Для нового запускаемого компонента указаны проверенные команды и конфигурация.
- Ссылки и схемы актуальны; отсутствуют секреты и персональные данные.

Документационный CI не заменяет тесты приложения. Лицензия распространения ещё не выбрана владельцем; не добавляйте случайный LICENSE от имени проекта.
